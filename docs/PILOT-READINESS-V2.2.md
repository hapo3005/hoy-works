# HOY Works – Pilot Readiness V2.2

Ziel: Der erste Pilot soll nicht nur „funktionieren“, sondern echte Nachfrage zuverlässig in passende Hilfe verwandeln.

## Startgates vor einem öffentlichen Pilot

### Netzwerk
- mindestens 2 **wirklich onboardete** Betriebe je kritischer Kategorie:
  - Klima
  - Sanitär
  - Elektro
  - Schlüssel / Schloss
- mindestens 1 onboardeter Betrieb je übriger Kernkategorie
- Einsatzgebiete serverseitig geprüft
- Sprachen durch Anbieter bestätigt, nicht geraten

### Produkt
- echter Kunde: Magic Link → Request → Match
- privates Foto: Upload → nur Kunde / zugewiesener Betrieb
- echter Betrieb: Lead → Annahme → Kontakt → Statuswechsel
- Cartagena/San-Javier-Grenzfall real getestet
- Abbruch-/Fehlerfälle getestet

### Pilot-Metriken
Im Pilot messen:
- Match Rate: Anteil der Requests mit mindestens einem qualifizierten Match
- Acceptance Rate: Anteil qualifizierter Requests, die ein Betrieb annimmt
- Time to First Acceptance
- Completion Rate
- Wiederholungsnutzung
- Anteil manueller Gemeindeprüfungen
- Anteil Requests ohne ausreichende Provider-Dichte

## Empfohlene Pilotgröße

Nicht sofort „ganz La Manga launchen“.

Besser:
1. 3–5 persönlich onboardete Betriebe
2. 20–30 kontrollierte reale Requests
3. Fehler und Friktion beheben
4. Provider-Dichte erhöhen
5. erst danach breiter vermarkten

## Erfolgsregel

HOY Works darf nicht wie ein Branchenbuch wachsen.

Die entscheidende Frage ist:
> Bekommt ein Nutzer mit einem echten Problem schnell einen tatsächlich passenden Betrieb?

Erst wenn diese Antwort zuverlässig „ja“ lautet, wird Reichweite skaliert.
